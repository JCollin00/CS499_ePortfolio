Animal Shelter Dashboard

Python • MongoDB • PyMongo • Dash • Plotly

Interactive shelter management tool originally built in CS 340 to query, visualize, and map animal rescue data.

Core Refactoring Goal: Upgrade the PyMongo CRUD layer with dynamic environment configurations, strict input validation, defensive exception handling, and safe visualization pipeline rendering.
100% Input Validation
PyMongo Exception Handling
CRUD Secure MongoDB Ops

Technical Refactoring Breakdown

Initial State (CS 340)

  • Hard-coded database connection strings.
  • Unvalidated query parameters passed directly to MongoDB.
  • Generic exception catching leading to potential app crashes.
  • Direct rendering of datasets without null/column checks.

Enhanced Architecture

  • Configurable Constructor: Environment-ready connection setup.
  • Defensive Validation: Parameter type & key verification raising explicit exceptions.
  • Robust Error Trapping: PyMongo-specific error capturing with clean fallbacks.
  • Safe Data Pipeline: Pre-render validation before updating Dash maps/charts.

Program Outcome Alignment

Outcome 2

Technical Documentation

Standardized Python docstrings, clean variable naming, and refactored module organization for long-term maintainability.

Outcome 4

Database Technologies

Applied advanced PyMongo data modeling, filtering strategies, and real-time dashboard data syncing.

Outcome 5

Security Mindset

Enforced input sanitization, prevented schema leakage, and handled database failures gracefully.

Reflective Summary

Refactoring this artifact reinforced that production-grade database engineering requires proactive input sanitization and graceful error handling over simple "happy-path" implementations.
